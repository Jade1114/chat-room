# 社团 / 组织持续发现与参与平台范围文档

## 1. 项目定位

本项目主线不再是普通聊天室，也不再是高校教学协作平台，而是一个面向社团 / 组织的持续发现与参与平台。

项目首先解决“一年一度社团招新日之外缺少稳定发现和加入渠道”的问题：用户可以随时发现组织、了解公开活动、查看组织主页并加入组织。进入已加入组织的频道交流是后续参与能力，不是第一痛点。

第一批典型场景包括：

- 高校社团，例如二次元社团、围棋社、游戏社团。
- 线上兴趣组织，例如游戏群、军事兴趣爱好群、同好交流群。
- 其他围绕共同兴趣、身份、活动或目标形成的组织。

高校和线上社区是主要落地场景，但核心模型不绑定学校、班级、课程或作业。

## 2. 核心产品主线

第一版围绕以下闭环展开：

```text
注册/登录
→ 默认加入官方组织 Public Square
→ 浏览组织大厅
→ 查看组织主页、公开活动和频道预览
→ 加入公开组织或通过申请码加入组织
→ 获得该组织默认频道访问权
→ 在组织频道中持续交流
→ 组织负责人维护组织资料和轻量活动，让组织在招新日之外保持可见
```

## 3. 核心概念

### 3.1 User

平台用户。用户可以在非招新季发现组织、了解公开活动、加入组织、进入已加入组织的默认频道，并参与交流。

### 3.2 Organization

组织是项目的核心实体。

组织不是单纯聊天群，而是围绕共同兴趣、身份、活动或目标聚集起来的群体。组织必须有对外展示内容，例如名称、简介、标签、活动等，这些内容让用户在错过招新日后仍然能判断是否值得加入。

第一版允许所有登录用户创建组织。创建者自动成为该组织的 Organizer，自动加入该组织，并获得组织默认频道访问权。

第一版新建组织默认公开，后续模型保留私密、草稿、审核、下架等安全治理扩展空间。

### 3.3 Public Square

Public Square 是平台方维护的默认官方组织。

用户注册后默认加入该组织。它既是所有用户的公共交流入口，也是给其他组织创建者参考的最佳示范组织。

### 3.4 Membership / OrganizationMember

用户和组织之间的成员关系。

组织可见性、组织成员关系、频道访问权需要分开：

- 用户可以看见公开组织，但不一定是组织成员。
- 用户加入组织后，才获得该组织默认频道访问权。
- 新用户默认只加入官方组织，因此默认只拥有官方组织频道。

### 3.5 Channel

频道是用户加入组织后的交流载体。

组织包含频道，频道属于组织。模型上一个组织可以有多个频道，但第一版每个组织只实现一个默认主频道。

用户口语上可以说“加入频道”，但领域模型里是“加入组织”，然后获得该组织默认频道访问权。

### 3.6 Activity

活动是组织发布的轻量展示信息，是用户判断组织是否活跃、是否值得加入的核心依据之一。

第一版 Activity 是独立实体，但不是完整活动管理系统。它可以包含标题、描述、时间、地点或链接、可见性等信息。

第一版不做报名、签到、人数限制、取消流程、活动通知或 RSVP。

### 3.7 InvitationCode

申请码/邀请码绑定组织。

用户通过申请码加入组织，而不是直接加入某个频道。第一版可保持简单，不做过期时间、使用次数限制或审核状态。

## 4. 第一版页面范围

### 4.1 Dashboard

用户登录后进入 Dashboard。

Dashboard 保留全局左侧路由布局，并在右侧主区域提醒用户完成核心操作：

- 进入官方组织频道。
- 创建自己的组织。
- 探索组织。
- 查看组织公开活动日程表。
- 在非招新季继续发现可能感兴趣的组织。

### 4.2 左侧导航

左侧采用上下两段式布局。

上段是偏操作的全局路由：

- Dashboard
- 组织大厅
- 我的组织
- 活动日程
- 创建组织

下段是用户已经参与的组织列表。第一版中，点击某个已参与组织，就是进入该组织默认频道。

### 4.3 组织大厅

组织大厅用于发现公开组织。

第一版支持：

- 公开组织列表。
- 关键词搜索。
- 标签筛选。
- 组织卡片。

组织卡片展示：

- 组织名称。
- 简介。
- 标签。
- 成员数。
- 最近或即将进行的活动摘要。
- 当前用户是否已加入。
- 加入组织或进入频道按钮。

### 4.4 组织详情页

组织详情页用于让非成员判断是否加入，让成员进入频道和查看活动，让 Organizer 维护组织。

第一版展示：

- 组织名称。
- 组织简介。
- 标签。
- 成员数。
- 组织负责人/创建者。
- 公开活动列表。
- 当前用户成员状态。
- 加入组织或进入频道按钮。

Organizer 额外可见：

- 编辑组织资料。
- 发布/编辑/删除活动。
- 查看成员列表。
- 查看或生成申请码。

### 4.5 我的组织

“我的组织”页面是组织关系管理页，不是左侧组织快捷入口的重复。

它展示：

- 用户已经加入的组织。
- 用户在每个组织里的身份：成员或 Organizer。
- 进入频道入口。
- Organizer 的管理入口。

第一版可以暂不做退出组织。

### 4.6 活动日程

活动日程第一版包含两个视图：

- 发现活动：展示公开组织的公开活动，用活动反向发现组织。
- 我的日程：展示用户已加入组织发布的活动。

因为第一版没有报名系统，“我的日程”表示“我加入的组织的活动”，不是“我报名的活动”。

### 4.7 创建组织

所有登录用户都可以创建组织。

创建组织后：

- 组织默认公开。
- 创建者成为 Organizer。
- 创建者自动加入组织。
- 系统自动创建该组织的默认频道。
- 该组织出现在组织大厅。

## 5. 第一版核心数据模型

第一版核心实体收束为：

```text
User
Organization
OrganizationMember
Channel
Activity
InvitationCode
```

暂不引入：

```text
ChannelMember
ActivityRegistration
OrganizationJoinRequest
ModerationAction
Notification
```

原因：

- 频道访问权从 OrganizationMember 推导。
- 活动不做报名。
- 公开组织默认可直接加入。
- 安全治理后续再做。
- 通知可以等事件系统阶段再接入。

## 6. 第一阶段实现顺序

第一阶段优先改领域主干，而不是先铺完整页面。

目标是先让以下链路跑通：

```text
组织包含默认频道
用户通过 OrganizationMember 获得频道访问权
官方组织 Public Square 在注册时默认加入
我的频道/我的组织频道列表从 OrganizationMember 推导
现有聊天链路继续基于 channelId 收发消息
```

建议顺序：

1. 新增 Organization / OrganizationMember / InvitationCode / Activity 基础模型或表。
2. 创建官方组织 Public Square。
3. 注册用户时默认加入官方组织。
4. 每个组织拥有一个默认 Channel。
5. “我的频道”改成“我已加入组织的默认频道”。
6. 现有 WebSocket 聊天链路继续基于 channelId，但频道访问权改由组织成员关系推导。

## 7. 暂不做

第一版暂不做：

- 完整活动报名系统。
- 多频道组织结构。
- 组织加入审核。
- 私密组织完整治理。
- 踢人、禁言、封禁。
- 复杂推荐算法。
- 组织内容审核后台。
- 通知系统。
- 活动 RSVP / 签到 / 人数限制。

这些功能不是不要，而是不要抢在组织、成员、默认频道、公开发现这条主链路之前实现。
